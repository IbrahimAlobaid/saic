# خطة تطوير منصة مجتمع الذكاء الاصطناعي السوري

**الهدف:** تحويل الصفحة التعريفية الحالية على `syrianai.org` إلى منصة ثنائية اللغة (عربي/إنجليزي) تعرض أعمال المجتمع وفعالياته وصوره بشكل منظم، مع صفحة «من نحن» تضم المؤسسين والمدربين والمتطوعين بفرقهم، وآلية رفع محتوى سهلة لا تحتاج لمس الكود، وبتكلفة تشغيل صفر.

**التاريخ:** 25 أكتوبر 2026 · **الحالة:** معتمدة المبادئ، جاهزة للبدء بالمرحلة 0

---

## 0. القرارات المعتمدة

| القرار | الاختيار |
|---|---|
| الاستضافة | **البقاء على GitHub Pages**، مع بناء تلقائي عبر GitHub Actions عند كل دفعة |
| من يدير المحتوى | **مجموعة صغيرة تبدأ بإبراهيم**، وتتوسع لاحقًا بإضافة حسابات GitHub للمؤسسين والمنظمين |
| التسجيل في الفعاليات | **روابط خارجية** لكل فعالية (Google Forms أو Luma أو غيرها) |
| اللغة | **عربي وإنجليزي من البداية**، العربية هي الافتراضية على `/` والإنجليزية على `/en/` |
| الفريق | داخل صفحة **من نحن** بترتيب: **المؤسسون ← المدربون ← المتطوعون**، والمتطوعون مقسومون إلى **فريق اللوجستيات، فريق الميديا، فريق العلاقات** |
| النشر | نشر مباشر للمجموعة الصغيرة الآن، وتفعيل سير المراجعة (مسودة ← موافقة) عند انضمام متطوعين للتحرير |

## 1. الوضع الحالي وما يفرضه

| البند | الحالي |
|---|---|
| الموقع | صفحة واحدة `index.html` ثابتة، هوية بصرية جاهزة (ليلي/فيروزي، خطا Cairo وSora) |
| الاستضافة | GitHub Pages من المستودع `IbrahimAlobaid/saic`، فرع `main` |
| النطاق | `syrianai.org` على Cloudflare (DNS فقط) مع HTTPS مفروض |
| المحتوى | نصوص الملف التعريفي، معسكر هندسة الذكاء الاصطناعي، 8 مدربين، روابط التواصل |
| من يحدّث | شخص واحد عبر git |

**ما يجب أن يبقى:** الهوية البصرية، الرابط `syrianai.org`، الأداء العالي، التكلفة الصفرية، GitHub Pages.
**ما يجب أن يتغير:** صفحة واحدة ← موقع متعدد الصفحات بلغتين يُغذّى من بيانات منظمة، ويُحدَّث من لوحة إدارة دون لمس الكود.

## 2. البنية التقنية

| الطبقة | الاختيار | لماذا |
|---|---|---|
| مولّد الموقع | **Astro** | ثابت وسريع، مجموعات محتوى بمخططات مُتحقَّق منها، تحسين صور تلقائي (WebP/AVIF ومقاسات متعددة)، توجيه i18n مدمج (`/` و`/en/`)، دعم RTL وLTR معًا |
| تخزين المحتوى | **ملفات Markdown/YAML داخل المستودع** | كل فعالية وشخص ومشروع ملف واحد بلغتيه، نسخ احتياطي وتاريخ تعديلات مجانًا عبر git، لا قاعدة بيانات |
| لوحة الإدارة | **Sveltia CMS** (متوافق مع Decap CMS) على `/admin` | واجهة عربية RTL، حقول ثنائية اللغة في نموذج واحد، رفع صور بالسحب والإفلات مع تصغير وتحويل تلقائي إلى WebP، تسجيل دخول بحساب GitHub |
| مصادقة اللوحة | **Cloudflare Worker** صغير (قالب sveltia-cms-auth الجاهز) على حساب Cloudflare الحالي | مطلوب لتسجيل الدخول بـ GitHub من المتصفح، مجاني، لا علاقة له بالاستضافة. وبديل مؤقت للمدير الوحيد: الدخول برمز وصول شخصي (PAT) دون Worker |
| البناء والنشر | **GitHub Actions** (`withastro/action` + `actions/deploy-pages`) | يبني الموقع عند كل دفعة إلى `main` وينشره على GitHub Pages خلال نحو دقيقتين، مع الإبقاء على ملف CNAME والنطاق كما هما |
| الصور الكبيرة لاحقًا | **Cloudflare R2** (10 GB مجانًا) | فقط إذا تجاوزت الصور حدود المستودع المريحة (~1 GB) |
| التحليلات | **Cloudflare Web Analytics** | بلا كوكيز، مجاني، يعمل مع أي استضافة |
| النماذج | **تضمين Google Form** لطلب التطوع في البداية | بلا خادم؛ ويمكن لاحقًا استبداله بنموذج مدمج عبر Worker |

**ملاحظة على GitHub Pages:** لا توجد معاينة تلقائية لكل Pull Request كما في Cloudflare Pages. البديل: معاينة داخل محرر اللوحة نفسها، وتشغيل محلي بأمر واحد (`npm run dev`) للمراجعات الكبيرة. هذا كافٍ لمجموعة تحرير صغيرة.

## 3. خريطة الموقع (بلغتين)

كل مسار له نظير إنجليزي تحت `/en/` مع مبدّل لغة في الترويسة وروابط `hreflang` لمحركات البحث.

| المسار | الصفحة | المحتوى |
|---|---|---|
| `/` | الرئيسية | تعريف مختصر، أقرب الفعاليات، أحدث الأعمال، أحدث الصور، دعوة للانضمام، روابط التواصل |
| `/about` | من نحن | الحكاية، الرؤية والرسالة، الأهداف، كيف نعمل، لمن نعمل، القيم، الأثر، ثم **الفريق**: المؤسسون ← المدربون ← المتطوعون (اللوجستيات، الميديا، العلاقات) |
| `/about/<slug>` | صفحة شخص | الصورة، الدور، النبذة، الروابط، الفعاليات والمشاريع التي شارك فيها (تُستخرج تلقائيًا) |
| `/events` | الفعاليات | قادمة وسابقة، تصفية حسب السنة والنوع (ورشة، معسكر، لقاء، هاكاثون، ويبينار) |
| `/events/<slug>` | صفحة فعالية | التاريخ والمكان، الوصف، المتحدثون، زر التسجيل (رابط خارجي)، التسجيل المرئي، معرض صور الفعالية |
| `/projects` | الأعمال والمشاريع | مشاريع التخرج ومشاريع الأعضاء ومبادرات المجتمع، تصفية حسب التقنية والسنة والبرنامج |
| `/projects/<slug>` | صفحة مشروع | الفريق، الوصف، التقنيات، روابط المستودع والعرض، صور |
| `/gallery` | المعرض | ألبومات مرتبة حسب الفعالية والتاريخ، عرض شبكي مع تكبير |
| `/programs/ai-engineering-camp` | البرامج | محتوى المعسكر الحالي، الدفعات، مع ربط بمشاريع التخرج |
| `/join` | انضم إلينا | نموذج التطوع (مضمَّن)، كيف تصبح مدربًا، الشراكات |
| `/admin` | لوحة الإدارة | Sveltia CMS (لا تُفهرس، بلا نسخة إنجليزية) |
| `/rss.xml`, `/sitemap.xml`, `/events.ics` | خلاصات | للمتابعة والتقويم ومحركات البحث |

## 4. نموذج المحتوى (المجموعات والحقول)

كل عنصر ملف واحد في `src/content/<collection>/` يحوي اللغتين معًا (كل حقل نصي له نسخة `ar` و`en`؛ إن غابت الإنجليزية تُعرض العربية مع إشارة). المخططات تُعرَّف بـ Zod وتمنع نشر عنصر ناقص.

### people (الأشخاص)
`name` {ar, en}, `slug`, `roles` (قائمة من: founder | trainer | volunteer)، `team` (للمتطوعين: logistics | media | relations)، `title` {ar, en} (المسمى)، `bio` {ar, en}, `photo`, `links` {`linkedin`, `github`, `website`, `x`}, `joined` (سنة)، `active`, `order`

الشخص قد يحمل أكثر من دور (مؤسس ومدرب مثلًا) فيظهر في كل قسم يخصه. ترتيب العرض داخل كل قسم بحقل `order` ثم الاسم.

### events (الفعاليات)
`title` {ar, en}, `slug`, `type` (workshop | camp | meetup | hackathon | webinar), `start`, `end`, `timezone`, `location` {`city` {ar, en}, `venue` {ar, en}, `online`, `url`}, `cover`, `summary` {ar, en}, `body` {ar, en}, `speakers` (مراجع إلى people), `registrationUrl` (رابط خارجي), `recordingUrl`, `album` (مرجع إلى albums), `tags`, `status` (يُحسب من التاريخ: upcoming | past، أو يُثبَّت cancelled), `featured`

### projects (الأعمال)
`title` {ar, en}, `slug`, `summary` {ar, en}, `body` {ar, en}, `team` (مراجع إلى people أو أسماء حرة لغير الأعضاء), `program` (مرجع إلى programs وكوهورت), `year`, `tech` (وسوم), `links` {`repo`, `demo`, `video`, `slides`}, `cover`, `gallery`, `featured`, `award` (اختياري)

### albums (الألبومات)
`title` {ar, en}, `event` (مرجع)، `date`, `cover`, `photos` [{`src`, `alt` {ar, en}, `credit`}], `visibility` (public | unlisted)

### programs (البرامج)
`title` {ar, en}, `slug`, `summary` {ar, en}, `body` {ar, en}, `cohorts` [{`name`, `start`, `end`, `trainers` (مراجع), `projects` (مراجع)}]

### partners (الشركاء)
`name`, `logo`, `url`, `type` (academic | company | community)

**نصوص الواجهة** (عناوين الأقسام، الأزرار، التذييل) في `src/i18n/ar.json` و`src/i18n/en.json`.

**قواعد الصور:** أقصى عرض عند الرفع 2000 بكسل، تحويل تلقائي إلى WebP بجودة 82، نص بديل إلزامي، تُخزَّن تحت `src/assets/uploads/<collection>/<slug>/` ليُولّد Astro المقاسات المتجاوبة عند البناء. أي صورة تحوي أشخاصًا تُرفع بعد موافقتهم (تنبيه ثابت في لوحة الرفع).

## 5. سير عمل الرفع والأدوار

| المرحلة | من يحرّر | كيف |
|---|---|---|
| الآن | إبراهيم (مدير المستودع) | `/admin` بحساب GitHub أو برمز PAT، نشر مباشر |
| قريبًا | المؤسسون ومنسق لكل فريق (3 إلى 5 حسابات GitHub بصلاحية كتابة) | `/admin`، نشر مباشر، الفرع `main` محمي من الحذف وإعادة الكتابة |
| لاحقًا | متطوعو فريق الميديا | تفعيل سير المراجعة في اللوحة: الحفظ ينشئ Pull Request يراجعه منسق ويدمجه |

**مثال: رفع صور فعالية بعد انتهائها**
1. افتح `syrianai.org/admin` وسجّل الدخول.
2. «الألبومات» ← «جديد»: اكتب العنوان بالعربية (والإنجليزية إن توفرت) واختر الفعالية من القائمة.
3. اسحب الصور (تُصغَّر وتُحوَّل تلقائيًا) واكتب وصفًا قصيرًا لكل صورة.
4. اضغط «نشر»؛ يدفع CMS الملفات إلى `main`، فيبني GitHub Actions الموقع وينشره خلال دقيقتين، ويظهر الألبوم في المعرض وصفحة الفعالية والرئيسية بلغتيه.

**مثال: إضافة متطوع جديد لفريق الميديا**
«الأشخاص» ← «جديد»: الاسم بلغتين، الدور «متطوع»، الفريق «الميديا»، الصورة، نبذة سطرين، رابط لينكدإن ← «نشر». يظهر تلقائيًا في قسم المتطوعين تحت فريق الميديا.

**الحماية:** لا أسرار في المستودع (مفاتيح OAuth في إعدادات Worker فقط)، كل تغيير له مؤلف وتاريخ في git، وصلاحية المدير لثلاثة أشخاص على الأقل عند توسع الفريق.

## 6. المراحل والتسليمات

### المرحلة 0 · التأسيس دون أي تراجع (4 أيام عمل)
- إنشاء مشروع Astro في المستودع نفسه مع i18n (`ar` افتراضية بلا بادئة، `en` تحت `/en/`)، ونقل التصميم الحالي إلى تخطيط ومكوّنات: Header (مع مبدّل اللغة), Footer, Section, Card, PersonCard, EventCard, Gallery.
- تقسيم الصفحة الحالية إلى `/` و`/about` و`/programs/ai-engineering-camp` بالمحتوى نفسه، وترجمة إنجليزية أولية للنصوص الحالية تُعرض للمراجعة قبل النشر.
- GitHub Actions للبناء والنشر على GitHub Pages مع الإبقاء على CNAME والنطاق؛ تحويل إعداد Pages من «فرع» إلى «GitHub Actions».
- **معيار القبول:** `syrianai.org` يبدو كما هو اليوم أو أفضل، و`syrianai.org/en/` يعمل، Lighthouse للأداء وإمكانية الوصول ≥ 90، لا روابط مكسورة.

### المرحلة 1 · البيانات المنظمة وصفحة من نحن بالفريق (5 أيام)
- تعريف المجموعات الست ومخططاتها ثنائية اللغة.
- إدخال البيانات الموجودة: المدربون الثمانية، المعسكر ودفعته، وقائمة المؤسسين والمتطوعين بفرقهم الثلاثة (تُزوَّد منك).
- أقسام الفريق في `/about` وصفحات `/about/<slug>`، وصفحات `/events`, `/events/<slug>`, `/projects`, `/projects/<slug>`.
- **معيار القبول:** إضافة فعالية أو شخص = ملف واحد، ويظهر في مكانه الصحيح بلغتيه تلقائيًا.

### المرحلة 2 · لوحة الإدارة والمعرض (5 أيام)
- نشر Worker المصادقة على Cloudflare وتهيئة Sveltia CMS بالعربية لكل المجموعات مع الحقول ثنائية اللغة.
- المعرض: ألبومات، شبكة متجاوبة، عرض مكبّر بلوحة المفاتيح، تحميل كسول، صور متعددة المقاسات.
- الروابط العكسية: الألبوم في صفحة فعاليته، والشخص يعرض فعالياته ومشاريعه.
- دليل مصوّر قصير في `docs/` لإضافة فعالية وألبوم وشخص.
- **معيار القبول:** رفع ألبوم 30 صورة ونشر فعالية خلال 10 دقائق من اللوحة دون لمس الكود.

### المرحلة 3 · الاكتشاف والجودة (4 أيام)
- صفحة `/join` بنموذج Google مضمَّن، وزر التسجيل الخارجي في كل فعالية.
- SEO: عنوان ووصف وصورة مشاركة لكل صفحة ولغة (صور OG تُولَّد تلقائيًا)، `hreflang`، بيانات Event المنظمة لظهور الفعاليات في Google، sitemap وRSS وملف تقويم `.ics`.
- التصفية والبحث داخل الفعاليات والمشاريع من جهة المتصفح.
- تدقيق إمكانية الوصول (WCAG AA) والأداء على الجوال باللغتين، وتفعيل Cloudflare Web Analytics.
- **معيار القبول:** كل صفحة بلغتيها لها معاينة مشاركة صحيحة، والموقع يحقق ≥ 90 في المحاور الأربعة.

### المرحلة 4 · التوسع (حسب الحاجة)
- تفعيل سير المراجعة للمتطوعين، نقل الوسائط الثقيلة إلى R2، نشرة بريدية، صفحة موارد، شهادات المشاركين، أرشيف التسجيلات.
- إن ظهرت حاجة لحسابات أعضاء وتفاعل لحظي: إضافة Supabase خلف الواجهة نفسها دون إعادة بناء.

**الإجمالي حتى نهاية المرحلة 3: نحو 18 يوم عمل**، قابلة للتوزيع على 3 إلى 4 أسابيع تقويمية.

## 8. المتطلبات غير الوظيفية

- **الأداء:** صفحة رئيسية أقل من 300 KB قبل الصور، صور متجاوبة بصيغ حديثة، لا جافاسكربت إلا عند الحاجة.
- **إمكانية الوصول:** تباين AA، تنقل بلوحة المفاتيح في المعرض، نص بديل إلزامي، احترام تقليل الحركة.
- **اللغة والاتجاه:** العربية RTL بخط Cairo، الإنجليزية LTR بخط Sora، أرقام وتواريخ منسقة حسب اللغة، مبدّل لغة يحافظ على الصفحة نفسها.
- **الأمان:** لا أسرار في المستودع، فرع محمي، رؤوس أمان عبر ملف `_headers` غير مدعوم في GitHub Pages فتُستبدل بوسوم `meta` حيث أمكن.
- **الاستمرارية:** المحتوى كله في git، ويمكن نقل الموقع إلى أي استضافة ثابتة خلال ساعة.
- **التكلفة:** صفر سوى تجديد النطاق.

## 10. ما يلزم لبدء المرحلة 1 (بعد المرحلة 0)

1. قائمة **المؤسسين** بالأسماء بلغتين، الصور، المسميات، نبذة قصيرة، روابط لينكدإن.
2. قائمة **المتطوعين** مقسومة إلى فرق اللوجستيات والميديا والعلاقات، بالبيانات نفسها، ومنسق كل فريق.
3. **الفعاليات السابقة** المراد أرشفتها: الاسم، التاريخ، المكان، نبذة، صور إن وُجدت.
4. **المشاريع** الجاهزة للعرض (مشاريع تخرج المعسكر وغيرها) بروابطها.
5. مراجعة **الترجمة الإنجليزية** الأولية للنصوص الحالية التي سأعدّها في المرحلة 0.

المرحلة 0 لا تحتاج أيًا من هذه البيانات ويمكن البدء بها فورًا.
